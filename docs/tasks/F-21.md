# F-21: fix a timing race in SettingsRepositoryTest

**Branch:** fix/f21-settings-test-race
**Goal:** `SettingsRepositoryTest > values persist across repository instances` passes every time instead of depending on timing.

## Context (read these first)
- `apps/android/app/src/test/java/dev/monet/app/core/settings/SettingsRepositoryTest.kt`: the test `values persist across repository instances` writes settings through a first repository whose DataStore lives in the coroutine scope `first`, calls `first.cancel()`, and immediately opens a second DataStore on the same file with the scope `second`.
- The failure seen in a fresh checkout: `IllegalStateException: There are multiple DataStores active for the same file`. `first.cancel()` only requests cancellation; DataStore releases the file when the scope's `Job` has completed, so the second DataStore can start too early.

## Files to edit
- `apps/android/app/src/test/java/dev/monet/app/core/settings/SettingsRepositoryTest.kt`: wait for the first scope to finish before opening the second DataStore.
- `docs/tasks/F-21.md`: fill the Worker report section.

The planner checks that the test fails before and passes after, runs the full unit suite several times, and updates `docs/BACKLOG.md`, `docs/PROGRESS.md` and `docs/tasks/LESSONS.md`; do not touch those.

## Do not touch
Everything else, especially every main source file under `src/main`, `build.gradle.kts`, `contracts/openapi.yaml`, any `.env` or `local.properties` file, and every other test.

## Behaviour (decided by planner)
- In the test `values persist across repository instances` only: replace `first.cancel()` with `first.coroutineContext[Job]!!.cancelAndJoin()`.
- The scope is created with `CoroutineScope(Dispatchers.IO + Job())`, so the `Job` exists; `Job` is already imported in that file.
- Add `import kotlinx.coroutines.cancelAndJoin`. The test body already runs inside `runBlocking`, so the suspend call is allowed.
- Do not change any assertion, any other test, or the repository classes.
