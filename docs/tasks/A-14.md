## Behaviour (decided by planner)
`RedisRateLimiter(client, per_minute: int, clock: Callable[[], float] = time.time)` with the same method `take(self, user: str, cost: float = 1.0) -> None`. `client` is a `redis.Redis` (synchronous).
- Fixed one-minute window: `window = int(clock() // 60)`; key `f"monet:rl:{user}:{window}"`.
- `count = client.incr(key, max(1, int(cost)))`. When `count == max(1, int(cost))` (the first hit in this window) call `client.expire(key, 120)` once.
- When `count > per_minute`: `retry = 60 - int(clock() % 60)` (always 1 to 60) and raise `Problem(429, "Too many requests", f"Retry in {retry}s", headers={"Retry-After": str(retry)})`, the same shape `RateLimiter` uses.
- Any `Exception` raised by `client.incr` or `client.expire` is logged with `log.warning("redis rate limit failed: %s", e)` (add `log = logging.getLogger(__name__)` and `import logging` to `auth.py`) and `take` returns normally: the limiter fails open and never breaks a request. A `Problem` must never be swallowed by this.
`build_rate_limiter(settings)` in `main.py`: returns `RedisRateLimiter(redis.Redis.from_url(settings.redis_url), settings.rate_limit_per_minute)` when `settings.redis_url` is set, otherwise `RateLimiter(settings.rate_limit_per_minute)`. Import `redis` at the top of `main.py` (`import redis`). `from_url` does not connect until the first command.

## Tests (no network except test 7; `FakeRedis` is a small class defined in the test file with a dict, `incr(key, amount=1)` returning the new int, and `expire(key, seconds)` recording its calls)
1. `per_minute=2`, `clock=lambda: 610.0` (window 10): the first two `take("u1")` return; the third raises `Problem` with `status == 429` and `headers == {"Retry-After": "50"}`.
2. Users are independent: with `per_minute=1`, `take("a")` then `take("b")` both return; a second `take("a")` raises.
3. Window reset: with `per_minute=1`, after `take("a")` at clock 610.0 is exhausted, `take("a")` at clock 660.0 (next window) returns.
4. Fail open: a client whose `incr` raises `ConnectionError("down")` makes `take("a")` return `None` without raising.
5. `expire` is called exactly once per key, with `120`, on the first hit only (two `take` calls on one user give one recorded `expire` call).
6. `build_rate_limiter`: `settings.model_copy(update={"redis_url": None})` gives a `RateLimiter`; `settings.model_copy(update={"redis_url": "redis://127.0.0.1:1/0"})` gives a `RedisRateLimiter` (no connection is made).
7. Real container, skipped when Redis is down: build `redis.Redis.from_url("redis://127.0.0.1:63790/0")`; if `ping()` raises, call `pytest.skip("redis container is not running")`. Otherwise use a fresh user id (`uuid.uuid4().hex`), `per_minute=2`, and check the third `take` raises `Problem` 429.
