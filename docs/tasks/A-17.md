# A-17: Supabase Storage answers a missing object with HTTP 400

**Branch:** feat/a17-storage-missing-object
**Goal:** `SupabaseBlobStore.get` of a missing key raises `FileNotFoundError` and `delete` of a missing key does nothing, also when Supabase answers with its real 400 body instead of a 404.

## Context (read these first)
- `services/api/src/monet_api/documents/store.py`: `SupabaseBlobStore.get` and `.delete` currently test only `response.status_code == 404`.
- `services/api/tests/test_supabase_blobstore.py`: `make_transport` and `make_store` (fake Supabase built on `httpx.MockTransport`) and the existing missing-key tests.
- Real Supabase behaviour (observed against the live project): a missing object returns HTTP 400 with JSON body `{"statusCode":"404","error":"not_found","code":"NoSuchKey"}`. A missing bucket returns the same 400 shape with `"code":"NoSuchBucket"`.

## Files to edit
- `services/api/src/monet_api/documents/store.py`: add a module-level function `_is_not_found(response)` and use it in `get` and `delete`.
- `services/api/tests/test_supabase_blobstore.py`: add one helper and four tests at the end of the file.
- `docs/tasks/A-17.md`: fill the Worker report section.

## Behaviour (decided by planner)
`_is_not_found(response: httpx.Response) -> bool`, placed above `class SupabaseBlobStore`:
- Parse `response.json()` inside `try/except ValueError`; a body that is not valid JSON, or not a JSON object, counts as "no body".
- If the body's `code` equals `"NoSuchBucket"`: return `False` (a missing bucket is a configuration error and must stay an error).
- Else return `True` when `response.status_code == 404`, or when the body has `statusCode` and `str(statusCode) == "404"`.
- Otherwise return `False`.
`get`: if `_is_not_found(response)` raise `FileNotFoundError(key)`; any other non-2xx still raises `RuntimeError("storage download failed with status <code>")`.
`delete`: if `_is_not_found(response)` return; any other non-2xx still raises `RuntimeError("storage delete failed with status <code>")`.
Error messages must still contain only the status code, never the key, the body or the service key. `put` is unchanged.

## Tests
Add this helper after `make_store`, then the four tests at the end of the file:
`def make_fixed_store(status: int, body) -> SupabaseBlobStore`: a store whose transport answers every request with `httpx.Response(status, json=body)`; `body` may be `None`.
1. `get("a.pdf")` when Supabase answers 400 with `{"statusCode":"404","error":"not_found","code":"NoSuchKey"}` raises `FileNotFoundError` (fails on the old code).
2. `delete("a.pdf")` with the same 400 answer returns without raising (fails on the old code).
3. Regression guard (passes on the old code): `get("a.pdf")` and `delete("a.pdf")` when Supabase answers 400 with `{"statusCode":"404","error":"Bucket not found","code":"NoSuchBucket"}` each raise `RuntimeError` whose message contains `400` and does not contain `a.pdf`.
4. Regression guard (passes on the old code): `get("a.pdf")` when Supabase answers 400 with `{"message":"bad request"}`, and when it answers 500 with no body, raises `RuntimeError`, not `FileNotFoundError`.
