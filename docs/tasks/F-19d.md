# F-19d: R8 code shrinking and resource shrinking for release builds

**Branch:** feat/f19d-r8-shrink
**Goal:** Release APKs are built with R8 (minify + resource shrink) so they are smaller, with keep rules that protect the serialization and network layers.

## Context (read these first)
- `apps/android/app/build.gradle.kts`: `buildTypes.release` currently has `isMinifyEnabled = false` and, when a keystore is configured, `signingConfig = signingConfigs.getByName("release")`.
- Libraries in use (they ship their own consumer rules): Retrofit with the kotlinx.serialization converter, OkHttp, kotlinx.serialization, Compose, DataStore, ML Kit text recognition (Chinese). The app's `@Serializable` data classes live under `dev.monet.app`.
- `apps/android/CLAUDE.md`: Android area rules.

## Files to edit
- `apps/android/app/build.gradle.kts`: enable R8 and resource shrinking for the release build type only.
- `apps/android/app/proguard-rules.pro`: NEW keep rules.
- `docs/tasks/F-19d.md`: fill the Worker report section.

## Who verifies what
The worker runs only the commands under Acceptance. The planner installs the release APK on the emulator and exercises the network and serialization path, and updates `docs/BACKLOG.md`, `docs/PROGRESS.md` and `docs/tasks/LESSONS.md`; do not touch those. If `assembleRelease` fails with "Missing classes detected while running R8", add the exact `-dontwarn` lines that the failure report suggests to `proguard-rules.pro`; do not weaken any other rule.

## Do not touch
Everything else, especially `contracts/openapi.yaml`, any `.env` or `local.properties` file, any keystore, `gradle/libs.versions.toml`, every Kotlin source file, and every test.

## Behaviour (decided by planner)
`build.gradle.kts`, inside `buildTypes { release { ... } }`: set `isMinifyEnabled = true`, add `isShrinkResources = true`, and add `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`. Keep the existing signing lines. Do not change the debug build type, the splits or the file naming.
`proguard-rules.pro` contains exactly these rules, each group under a one-line `#` comment:
- Attributes: `-keepattributes Signature,InnerClasses,EnclosingMethod,RuntimeVisibleAnnotations,AnnotationDefault`
- kotlinx.serialization for the app's own classes: `-keepclassmembers class dev.monet.app.** { *** Companion; }`, `-keepclasseswithmembers class dev.monet.app.** { kotlinx.serialization.KSerializer serializer(...); }`, `-keep,includedescriptorclasses class dev.monet.app.**$$serializer { *; }`
- Retrofit service interfaces: `-keep,allowobfuscation,allowshrinking interface dev.monet.app.core.network.MonetService` (the internal interface declared in `RemoteMonetApi.kt` that Retrofit creates; `MonetApi` is the app-facing interface and needs no rule)
- Optional TLS providers that OkHttp mentions but Android does not ship: `-dontwarn okhttp3.internal.platform.**`, `-dontwarn org.conscrypt.**`, `-dontwarn org.bouncycastle.**`, `-dontwarn org.openjsse.**`
Debug builds stay unminified so stack traces and the emulator workflow do not change.
